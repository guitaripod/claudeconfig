# App Store work

## Always use the `asc` CLI
- Every ASC interaction goes through `asc` (rorkai/App-Store-Connect-CLI, https://asccli.sh, `~/.local/bin/asc`). Never hand-roll ASC REST calls, JWT helpers or one-off submit scripts unless `asc` provably lacks the endpoint: say so, then fall back to `python3 ~/.config/midgar/asc-token.py`.
- Read the `asc-cli-usage` and `asc-workflow` skills (plugin `asc@rorkai`) before a release flow. `asc search "<what you want>"` when unsure. Prefer `--output json` when parsing.
- Auth is registered once per machine from the midgar vault: `source ~/.config/midgar/credentials.env && asc auth login --name midgar --key-id "$ASC_KEY_ID" --issuer-id "$ASC_ISSUER_ID" --private-key "$ASC_PRIVATE_KEY_PATH" --network`; check with `asc auth status`. Vendor number for all sales/finance reports: `93803823`.
- Go-to commands: `asc apps list --paginate --output table` (IDs), `asc status --app <id>` (release dashboard), `asc analytics sales --vendor 93803823 --type SALES --subtype SUMMARY --frequency DAILY --date YYYY-MM-DD`, `asc analytics compare --source sales --vendor 93803823 --app <id> --from … --to … --frequency MONTHLY --output table`, `asc finance reports --vendor 93803823 --report-type FINANCIAL --region ZZ --date YYYY-MM`, `asc reviews list --app <id>`.
- Gotchas: `analytics compare --frequency DAILY` over ~30 days hits its request deadline, loop `analytics sales` per day instead. IAP rows carry the product name in `Title` and the app's SKU (e.g. `flaccy-ios`) in `Parent Identifier`: filter on parent/SKU, never on the app title, or purchases come out as zero.
- Fresh machine: `curl -fsSL https://asccli.sh/install | bash`, then `claude plugin marketplace add rorkai/app-store-connect-cli-skills && claude plugin install asc@rorkai` (`asc install-skills` writes `~/.agents/skills/`, which Claude Code does not read).

## Midgar operations vault (macbook)
`~/.config/midgar/` (chmod 600, never in git): `credentials.env` (ASC API key/issuer, RevenueCat v2 secret keys per project, signing paths), `signing/` (distribution p12 + password, provisioning profiles, AICredits deploy key), `OPERATIONS.md` (App Store Connect, RevenueCat, the mako credits backend, release-CI mechanics). Read `OPERATIONS.md` first for any store, revenue or release work and keep it accurate afterwards.

## What's New: rich, every release, every platform
List everything a user actually gets since the last release that reached *that* store. A version that shipped Mac-only or was skipped folds its work into the next one's notes: walk `git log` back to the previous release commit for that platform, never just the headline feature or last commit. Write en-US concrete and user-facing (features, fixes, what changed on screen; no "bug fixes and improvements"), translate into every locale the listing already carries, then read the notes back from the store. Same rule for TestFlight what-to-test, GitHub release notes and changelogs.

## Never upload binaries built on a beta macOS
Apple rejects them after submission with ITMS-90111 ("must use the latest Xcode and SDK Release Candidates"). The message is boilerplate; the real trigger is `BuildMachineOSBuild` in the app's Info.plist carrying a beta host build number (digits + letter + `5xxx` + trailing lowercase letter, e.g. `26A5353q`), even with release Xcode/SDK. Diagnose with `sw_vers -buildVersion` on the build host and `PlistBuddy -c "Print BuildMachineOSBuild" App.app/Info.plist` on the artifact.
- Standard method while the Mac runs a beta: `buildvm` (repo `~/Dev/buildvm`, guitaripod/buildvm, on PATH), a stable-macOS Tart guest that archives, signs and uploads over SSH, so the artifact carries the guest's stable build number. Read its `AGENTS.md` first. Machine-local config at `~/.config/buildvm/config.env` (points at the midgar vault). One command per release, e.g. `buildvm build --dir <proj> --scheme <s> --profile <app.mobileprovision> --profile <widget.mobileprovision> --build <N> [--marketing <V>] [--env KEY=VAL …] [--component MetalToolchain] [--deploy-key <key>] [--archive-flags "…"]`. Pass every `${VAR}` the project.yml references as `--env` (else blank bundle id and App Intents "Unable to parse Info.plist"); never `--unsigned-archive` an app with entitlements (drops game-center/healthkit/weatherkit/app-groups and the submit 409s `BUILD_INDICATES_*_DISABLED`); one `--profile` per signed target. Snapshot `buildvm-provisioned` is the reusable base. Once the Mac's macOS is GM, plain local `xcodebuild` is legal again.
- Fallback: a stable-macOS GitHub Actions runner with manual signing (p12 + profile + ASC key as secrets, `altool --upload-app`); reference `guitaripod/master-of-flags` `.github/workflows/testflight.yml`, which also fails the run if the runner's build number matches the beta pattern. Costs quota (macOS runners bill at 10x).
