Give a "best thing to buy SECOND-HAND in Finland" recommendation grounded in LIVE listings on Tori.fi (classifieds) and Huuto.net (auctions + buy-now) for "$ARGUMENTS". Coverage is Tori.fi + Huuto.net only (Facebook Marketplace is not searchable).

Run `date +%F` (Bash) for today; the used market moves fast, so treat training knowledge as possibly stale.

## Scope — decide the mode

- **product**: one specific thing to buy used (e.g. "iphone 13 128gb", "rtx 3080", "herman miller aeron"). Use a short exact search string, plus a BROADER core query with capacity/colour/spec qualifiers dropped ("iphone 13 128gb" → "iphone 13") — Huuto.net matches ALL words strictly, so a too-specific query returns nothing and the broad one is filtered down later. Define mustMatch tokens (defining model/capacity/size) and accessory terms to DROP (phone: kuori, suojakuori, case, lasi, laturi, panssarilasi, kaapeli…). If it's electronics new shops carry, also price it new for the used-vs-new saving.
- **category**: an open "what used thing is best" question (e.g. "good used road bike under 800"). WebSearch the CURRENT well-regarded picks, shortlist 4-6 concrete, buyable-used models (exact names incl. defining size/spec), and check each.
- **build**: assemble a multi-part system from used parts (gaming PC, home-office setup, camera kit), usually anchored on one named part. Design ONE coherent, compatible, non-bottlenecked build: single platform (for a PC that means one socket + matching chipset + right RAM gen — AMD AM4/DDR4 is the used-market value sweet spot), parts matched to the anchor's level (a 1080 Ti needs ~650W PSU with 8+6-pin; case must fit board + GPU length; skip a separate cooler if the CPU is boxed). If the user names a part they already own, treat it as owned (compat only, don't price it); if they name one as the anchor, source it used too and say which you assumed. Allocate the budget across parts. For each part set a short searchQuery, broad coreQuery, mustMatch/accessoryTerms, targetSpec, and a newPriceQuery if the part is still sold new (RAM/SSD/PSU/case/current CPUs; null for discontinued parts like a 1080 Ti).

## Hunt — pull live listings

For the product (and per part / per candidate in the other modes):

- **Tori.fi**: `webfetch` `https://www.tori.fi/recommerce/forsale/search?q=<url-encoded query>` and parse every for-sale listing from the page: title, price in EUR, location, absolute listing URL under tori.fi/recommerce/forsale/item/. Up to 30, only real listings that show a price.
- **Huuto.net**: Bash `curl -sL "https://api.huuto.net/1.1/items?words=<url-encoded coreQuery>&status=open&page=1"` and `...&page=2`, parse the "items" array: title, currentPrice, buyNowPrice, saleMethod ("buy-now" | "auction" | "buy-now-and-auction"), location, closingTime, bidderCount, links.alternative (use THIS as the url). The words search is intentionally broad — filter down, don't add words.
- **New reference** (product mode, and per part where a newPriceQuery exists): `hinta compare "<query>" --enrich --devices-only --json`, take the cheapest in-stock offer of the right variant as the NEW price.

Keep ONLY genuine listings of the target (title consistent with ALL mustMatch tokens), DROP accessories/parts/cases/lookalikes (any accessory term), and drop clearly-different variants. For each listing record: title, priceEur (asking price / buy-now price; for a pure auction the current bid), auction flag, buyNowEur, currentBidEur, location, url, closingTime, bidderCount, condition and warrantyMonths ("TAKUU 12kk" → 12) if stated, sellerType ("dealer" if it reads like a reseller with bulk/ALE/TAKUU branding, else "private"). Max 25 per source, cheapest first. NEVER invent a listing, price, or url. Issue the source fetches in parallel.

## Appraise — compute the fair band and flags (do this arithmetic yourself, show the numbers)

From the FIXED-price listings (auctions excluded), compute: min, 25th percentile, median, 75th percentile, max (linear interpolation between sorted values). Flag each fixed-price listing: `< median × 0.55` → **suspicious-low** (likely broken/parts/scam — never recommend one), `> median × 1.6` → **overpriced**. If the user gave a budget, drop listings over 1.15× budget first. Sort by price, keep ~30.

## Recommend

- **product/category**: 1. **Top pick** — the best-VALUE listing to actually buy (not merely cheapest): weigh price vs. condition, warranty, seller type (dealer with warranty is safer but pricier), location vs. any preferred region, and auction risk. Give title, price EUR, source, location, URL, one line why. In category mode, say which MODEL it is and why it's the right used pick. 2. **Fair price band** — typical used range + median in one line, and the saving vs. new (median vs. new reference, % and EUR) when known. 3. **Cheapest legit option** — lowest listing NOT flagged suspicious-low. 4. **Watch out** — the suspicious-low listings (never buy) and any live auction whose current bid understates the cost. 5. One line of buyer advice fit to THIS item (phone: IMEI / iCloud lock / battery health, meet in person; bike: frame/serial; etc.).
- **build**: 1. **Component route** — exactly ONE listing per buyable part, best value, genuine loose part (not a whole PC), not suspicious-low, compatible. One line per part: **<Label>** — <title>, **<price> €**, <source>, <location> — <URL> · one clause why. Owned parts as "you provide"; parts with no loose listing are GAPs with their new-price fallback (cite newRef price + retailer). 2. **Donor route** — if several parts are gaps, look for ONE whole used PC on the same platform bundling most parts (CPU+board+RAM+storage+PSU+case) and add the anchor part to it (swapping/reselling its GPU). 3. **Total & recommendation** — EUR totals of BOTH routes (component = used loose parts + gaps bought new; donor = donor PC + anchor), saving vs. new, budget fit, and the lower coherent total wins (if loose parts were plentiful, say the component route simply wins). 4. **Compatibility check** — 2-3 lines: socket = socket, RAM gen matches, PSU wattage + PCIe connectors for the GPU, case fits board + GPU length; for a donor PC verify its PSU/case accept the anchor GPU; swap to compatible listings from the data if needed. 5. **Watch out** — rejected suspicious-low listings, whole-PC listings excluded from the component route, live auctions. 6. **Buyer advice** — 1-2 lines: stress-test the GPU for artifacts / mining wear, inspect CPU socket pins, avoid 7+ yr PSUs, test-boot before paying, meet in person.

Rules: prices are EUR and live. Never invent a listing, price, seller, or URL. Never recommend a suspicious-low listing as a buy. Keep every pick compatible. Be factual and tight — the buyer should know exactly which listings to open and what it totals.
